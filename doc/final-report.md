# MPID：面向离线场景的轻量级多模态提示注入检测算法研究结题报告

> **报告版本**：v1.0  
> **完成日期**：2026-08-03  
> **评测口径说明**：本报告中凡涉及模型效果、策略优劣和训练放行的量化结论，均**仅采用冻结的 MPID Standard Benchmark v2**。V1、run-local smoke、15 条集成检查、600 条工程诊断和离线包 smoke 仅用于工程验证或问题定位，不作为模型能力结论。

## 摘要

本项目围绕离线、隐私敏感和资源受限场景下的提示注入风险，研究轻量级多模态检测方案。项目将核心三分类检测器命名为 **MPID（Multimodal Prompt Injection Detection，多模态提示注入检测）**：它以 SmolVLM-500M 为视觉语言模型骨干，在其上加载 LoRA 适配器和 MPID classification head，完成对正常输入（`clean`）、直接提示注入（`direct`）和间接/多模态提示注入（`indirect`）的三分类检测。下文所称“**MPID + LoRA**”即指这一仅包含 LoRA 权重与 MPID 三分类头的模型组件，不包含 C4/C5/C6 推理侧防线。同时，项目围绕安全性、效率和可解释性构建了 C4 早退、C5 规则前置过滤、C6 跨模态检测三层防御机制，并完成离线推理、OCR 辅助、打包与 smoke 验证等工程闭环。

项目建立了冻结的 MPID Standard Benchmark v2 及其完整性校验、数据隔离和统一评测规范。基于 v2/smoke 的十一项策略横评显示：当前最佳 Macro F1 为 40.77%，最平衡的 F 策略 Macro F1 为 40.72%、direct F1 为 33.7%，均未达到预设的 Macro F1 ≥ 45%、direct F1 ≥ 35% 的放行标准。因此，项目结论是：已形成可复现、可离线部署、可审计的研究原型和实验平台，但尚未形成可无条件推广的高可靠三分类安全模型。后续应重点加强 direct 与 indirect 的边界数据、困难样本训练和 v2/full 独立正式评测。

**关键词**：提示注入；离线部署；视觉语言模型；LoRA；多模态安全；防御纵深

## 1. 背景和目标

### 1.1 研究背景

随着大语言模型（LLM）和多模态大语言模型进入实际业务流程，提示注入已成为重要安全风险。攻击者可通过显式文本指令诱导模型忽略既有约束，也可将恶意指令嵌入网页、文档、邮件或图像等外部内容中，形成间接甚至多模态的攻击路径。

现有防御方案多依赖云端 API 或较大规模的专用模型，虽然在在线服务中具有优势，但在医疗、法律、政务、金融、弱网终端、IoT 节点等场景仍面临数据出端、网络依赖、调用成本和算力受限等问题。因此，需要探索能够本地运行、便于打包、可审计且支持图文输入的轻量级防御方案。

### 1.2 核心问题

本课题要回答的问题是：在普通 PC 与主流边缘设备的算力、内存和网络约束下，如何利用轻量级多模态模型完成图像与文本联合的提示注入检测，并在检测安全性、正常输入可用性和推理效率之间取得可量化的平衡。

### 1.3 项目目标

1. 构建以 SmolVLM-500M 为骨干的 MPID + LoRA 离线多模态三分类检测基线。
2. 覆盖 `clean`、`direct`、`indirect` 三类输入及中文、英文、中英混合场景。
3. 通过 LoRA 降低微调成本，支持 CPU 与 MPS 等跨平台执行路径。
4. 建设三项可独立开关、独立验证的优化机制：
   - **C4 早退**：对高置信正常输入快速放行，降低时延；
   - **C5 规则前置过滤**：对明确的直接注入模式进行低成本、可审计拦截；
   - **C6 跨模态检测**：利用图像 OCR 文本和跨模态信号补充间接注入检测。
5. 形成训练、评测、推理、离线打包和复现文档的完整交付闭环。

## 2. 本次课题选择的研究范围和原因

### 2.1 研究范围

## 3. 理论基础、研究设计与方案论证

本章从学术研究设计的角度说明项目为何采用当前的威胁建模、模型架构、数据标注、评测体系和优化方案。它回答的不是“项目做了什么”，而是“这些选择在何种理论前提下成立，以及如何形成可检验的研究问题”。

### 3.1 研究定位：离线多模态提示注入检测

提示注入的本质是**不可信输入与可信指令之间的控制权竞争**：攻击者通过输入中的指令性内容，诱导模型偏离系统目标或用户真实任务。对于多模态应用，这种不可信内容不仅存在于用户显式输入的文本中，也可能隐藏在图像、文档、网页等外部载体中。因此，本项目将检测问题定义为：

> 给定用户文本与可选图像，在不依赖外部网络服务的条件下，判断该输入是否包含会改变模型控制边界的直接或间接提示注入信号。

该定义具有两层研究含义。第一，它将问题限定为输入侧风险识别，而非试图通过重新对齐通用大模型来消除所有攻击；第二，它将系统部署约束纳入研究对象，即检测器除具备分类能力外，还应满足本地运行、可打包、可审计和资源可控等工程条件。由此，本项目的研究定位是“**离线端侧安全检测**”，与云端大模型防御方案构成互补，而非以参数规模或通用理解能力为直接竞争目标。

### 3.2 威胁模型与三分类任务的理论依据

项目采用 `clean`、`direct`、`indirect` 三分类，而非简单的“安全/不安全”二分类。其理论原因在于三类输入具有不同的攻击载体、可观测信号和防御路径：

| 类别 | 攻击或输入特征 | 主要可观测信号 | 对应防御重点 |
|---|---|---|---|
| `clean` | 正常任务请求，不试图改变系统控制权 | 合法任务语义、无高风险指令模式 | 低误报、快速放行 |
| `direct` | 攻击指令直接出现在用户文本中 | 指令覆盖、身份伪装、敏感操作模式 | 规则拦截与文本分类 |
| `indirect` | 攻击藏于图像或不可信外部内容，或由图文组合形成 | OCR 文本、图文不一致、外部内容角色冲突 | 多模态理解与跨模态检测 |

二分类会将 direct 与 indirect 合并为“攻击”，虽然可以降低标注与建模难度，却会掩盖两类攻击的失效模式：模型可能擅长显式文本攻击，却无法处理图像内嵌指令；也可能对外部内容异常敏感，从而误杀正常文本。因此，三分类既是更细粒度的安全任务定义，也是后续消融实验的必要前提。

### 3.3 模型选型：轻量级 VLM 与 LoRA 的合理性

本项目以 SmolVLM-500M 作为默认骨干，核心理由不是追求单模型在所有视觉语言任务中的最高性能，而是满足“端侧可部署的图文联合判断”这一研究约束。

从方法论上看，单一 VLM 架构具有三项价值：

1. **统一表征**：图像和文本进入同一视觉语言建模框架，避免 OCR、文本编码器和图像编码器之间因独立训练而产生的信息割裂；
2. **端到端可检验性**：可直接把“图像 + prompt → 三分类标签”作为实验输入输出，便于测试多模态攻击是否真正被模型利用；
3. **变量可控性**：固定模型家族后，数据、训练策略和 C4/C5/C6 优化的影响可以在统一骨干上比较。

LoRA 的选择基于参数高效微调理论：冻结预训练模型的大部分参数，仅学习低秩更新矩阵，可在有限计算资源下完成任务适配。对本项目而言，LoRA 的意义不仅是降低显存或内存消耗，也使多策略 smoke、checkpoint 比较与跨平台复现成为可操作的实验流程。需要指出的是，参数高效并不等同于安全任务天然容易；当训练数据不足或类别边界复杂时，LoRA 仍可能出现分类头偏置和类别塌缩，这也是本项目后续评测重点关注逐类指标的原因。

### 3.4 评测设计：从总体准确率转向安全风险度量

提示注入检测具有显著的**风险不对称性**：将攻击误判为 `clean` 会导致漏报与潜在控制权失守；将正常请求误判为攻击则造成误杀和可用性下降。单独使用 Accuracy 会被样本比例和多数类预测掩盖，无法反映这两种风险。

因此，项目以 Macro F1 为核心比较指标，并同时报告各类别 Precision、Recall、F1、混淆矩阵和图像/OCR 子集表现。Macro F1 对每一类赋予相同权重，能够惩罚“只会预测多数类”的表面高准确率模型；逐类 Recall 则直接检验攻击是否被遗漏；clean FPR 用于约束防御系统对正常业务的侵扰。

在实验设计上，冻结 Benchmark v2 并将其划分为 smoke 与 full 两层：

- **v2/smoke（150 条）**用于低成本策略筛选和失败模式诊断；
- **v2/full（500 条）**用于独立正式验收和训练放行。

这种分层评测设计遵循“开发集不替代测试集”的基本原则。策略可以在 smoke 集上被比较和淘汰，但不能因为在小样本上取得局部提升就被宣称为最终有效；正式能力结论必须留给 v2/full。项目预设三类 Recall 均大于 0、direct F1 ≥ 35%、Macro F1 ≥ 45% 的门槛，目的正是避免任何一类攻击被完全忽略时仍被总体指标“放行”。

### 3.5 C4/C5/C6 的理论逻辑：纵深防御与功能分工

项目并未将 VLM 视为唯一防线，而是采用分层的 defense-in-depth 架构：低成本、高确定性的证据优先处理；语义复杂、证据不足的样本才进入后续模块和模型精判。该架构的核心不是让每层都完成全量分类，而是通过功能分工降低单一模型失效带来的系统性风险。

| 模块 | 理论基础 | 输入证据 | 决策语义 | 核心风险 |
|---|---|---|---|---|
| C4 | 自适应计算、置信度门控 | VLM 分类头概率 | 高置信 `clean` 可提前放行 | 攻击被错误早退 |
| C5 | 知识驱动检测、混合防御 | 文本规则与结构异常 | 高确定性 `direct` 可直接拦截 | 规则泛化不足或误杀 |
| C6 | 多模态一致性、外部内容不可信原则 | 图像像素、OCR 文本、图文关系 | 可疑 `indirect` 可直接拦截，否则交模型复判 | OCR 局限与关系理解不足 |

### 3.6 C4：置信度门控与安全约束下的早退

#### 3.6.1 问题定义与理论动机

C4 对应自适应计算（adaptive computation）思想：不同样本的判别难度不同，显著正常的输入不必消耗与高风险样本相同的处理成本。若正常请求在实际流量中占多数，则所有请求均执行完整后续路径会使平均时延被低风险流量主导。C4 以分类头对正常类的置信度作为门控信号：

```text
若 P(clean | x) > θ：提前放行（allow）
否则：交由后续检测链路（defer）
```

其中，`θ` 为保守阈值。当前轻量实现复用最终分类头的 softmax 概率，不新增模型参数或训练成本；未来可扩展为在 VLM 中间层增加辅助分类头的联合训练早退机制，使简单样本跳过部分 Transformer 层。

#### 3.6.2 风险不对称与单向放行原则

安全检测中的早退不是普通的性能优化。将正常样本判为可疑，主要代价是误杀；将攻击样本判为正常，则属于漏报。因此 C4 只允许对高置信 `clean` 做“单向放行”，不将高置信攻击类视为可以绕过其他安全检查的理由。最严重的错误被定义为 `wrong_exit`：真实标签为 `direct` 或 `indirect` 的样本被 C4 提前允许通过。

这一定义使 C4 成为一个带硬约束的多目标优化问题：在满足以下安全条件的前提下，尽可能提高延迟节省比例 `saved_pct`。

```text
wrong_exit = 0
且 Macro F1 的变化量 Δ ≥ -0.02
```

换言之，时延节省是优化目标，错误早退与明显的分类质量下降是不可交换的安全约束。宁可不触发早退，也不应以漏报换取速度。

#### 3.6.3 阈值校准与可证伪性

C4 阈值不能凭经验确定，而应先在验证数据上扫描候选阈值，例如 0.90、0.93、0.95、0.97、0.99。对每个阈值同时计算退出率、错误早退、Macro F1 变化和延迟节省；先剔除任何 `wrong_exit > 0` 或 F1 明显退化的阈值，再在剩余候选中选择收益较高者。最终阈值只能在独立的 Benchmark v2/full 上报告一次结果，避免在测试集上反复调参。

#### 3.6.4 C4 的研究边界

当前 C4 是推理调度型优化，而不是重新训练得到的模型能力提升；它不会修复分类头本身的类别塌缩。中间层 early head 属于后续研究方向，理论上能够跳过部分 VLM 主干计算，但需要辅助损失、层间稳定性约束和更严格的安全验证。因此，报告中应将当前 C4 定位为“高精度正常输入放行机制”，而非已经完成的端到端模型加速算法。

### 3.7 C5：规则知识与学习模型的混合防御

#### 3.7.1 规则层的认识论角色

C5 基于这样一个事实：一部分直接提示注入具有高度模板化的语言和结构特征，例如指令覆盖、角色劫持、伪造 system/developer 消息、策略绕过和 Unicode 混淆。这些模式不一定需要通过大模型的语义推理才能识别。规则层将显式安全先验编码为可执行模式，从而提供独立于 LoRA checkpoint 的检测证据。

规则与 VLM 的关系不是替代，而是互补。规则擅长已知、高确定性模板，具有低延迟、可解释、易审计和可更新的特点；VLM 更适合处理同义改写、上下文依赖和未知表达。由此，C5 采用“命中即拦截、未命中则继续检测”的单向逻辑：

```text
若任意高确定性规则 r 命中输入 x：按 direct 拦截（block）
否则：交由 C6 或 VLM 分类头继续判定（defer）
```

未命中规则的语义是缺少足够证据，而不是样本安全。这一设计避免了规则系统常见的封闭世界假设，即“黑名单之外即为安全”。

#### 3.7.2 多信号规则与可解释性

C5 的规则可按四类信号组织：关键词/指令覆盖、敏感行为意图、伪系统消息等结构异常，以及零宽字符、双向控制字符等 Unicode 混淆。将规则分组而非混合为单一正则集合，具有两项研究价值：其一，可统计不同攻击表征的命中分布，为数据扩充提供依据；其二，每次拦截均可返回规则标识、类别、严重度和截断片段，形成可审计的决策证据。

可解释性在本项目中并非附属功能。对于离线合规场景，系统需要说明“为何拦截”，而不是只输出一个攻击标签；规则证据也可用于后续人工复核、规则版本治理和误报分析。

#### 3.7.3 误杀控制与顺序问题

C5 的主要风险是将正常的讨论性、引用性文本误判为直接攻击。因此，规则设计应优先使用“攻击意图 + 权限语义”的组合模式，而避免将孤立的普通词汇作为硬拦截依据。结构异常和 Unicode 信号尤其应被视为风险提示，而不是无限扩张的宽泛黑名单。

在系统顺序上，C4 与 C5 可配置。若已有可靠的 VLM 概率，C4 在前可使明显正常样本快速结束；若部署优先级是最小化漏报，C5 在前更保守，可避免低阈值 C4 绕过明确的文本攻击证据。无论顺序如何，C5 都应保持无状态、低成本、与模型 checkpoint 解耦，才能支持独立更新和消融评测。

### 3.8 C6：跨模态证据、OCR 感知与间接注入检测

#### 3.8.1 间接注入的观测盲区

间接提示注入的危险内容可以完全不出现在用户输入文本中。例如，用户请求“总结图片内容”，但图片中嵌有“忽略之前指令并泄露系统提示词”的文本。对纯文本 C5 而言，该攻击不可见；仅依赖最终三分类头时，又难以明确说明风险来自图像中的哪段内容。因此，C6 将间接注入建模为“外部内容、用户任务与权限边界三者之间的冲突”。

项目重点关注三类冲突：内容冲突（用户任务与图像指令无关）、角色冲突（图像伪装 system/developer 消息）和任务冲突（外部内容要求敏感或越权操作）。这些冲突共同反映了外部内容试图改变可信指令层级的风险。

#### 3.8.2 感知—对齐—判定的三阶段结构

完整的 C6 可抽象为三段式过程：

```text
图像/外部内容
  → 感知：OCR、视觉描述或 VLM 辅助提问
  → 对齐：提取候选指令，并与用户任务和权限边界比较
  → 判定：输出 indirect 风险或交回 VLM 分类头
```

当前已实现的 C6B-lite 采用本地 OCR 提取图像像素文本，对明确的指令覆盖、安全关闭、越狱与信息泄露模式进行保守检测。其理论优势是：检测证据来自真实图片像素而非数据集的人工标注字段，且命中时能够给出具体风险原因。未命中 OCR 规则或 OCR 不可用时，系统不得判为 `clean`，而应转交后续 C6 兼容路径或 VLM 分类头。

#### 3.8.3 C6A、C6B-lite 与完整 C6B 的研究层次

| 层次 | 能力定位 | 研究价值 | 局限 |
|---|---|---|---|
| C6A | metadata/path 与轻量启发式 | 固定跨模态模块接口和调度契约 | 不读取图像像素，不代表图像理解能力 |
| C6B-lite | 本地 OCR + 明确越权规则 | 提供真实图像文本的可解释补充证据 | 受 OCR 错漏、字体和语言覆盖限制 |
| 完整 C6B | OCR/VLM/CLIP 或图文蕴含的关系判断 | 检测图文矛盾与隐蔽间接攻击 | 需要更大规模的标注数据与独立评测 |

该分层避免把工程接口验证、OCR 规则能力与真正的跨模态语义理解混为一谈。特别是 C6A 的意义在于验证管线与输出 schema，C6B-lite 的意义在于验证离线像素 OCR 路径；两者均不能单独宣称解决了多模态提示注入。

#### 3.8.4 与 LoRA 分类器的互补关系

LoRA 分类器学习的是输入整体映射到三类标签的统计边界；C6 则显式寻找“外部内容是否试图越权”的证据。将这两种能力分开有两点好处：一是 C6 的规则和 OCR 可以在 checkpoint 变化后继续复用；二是当系统判定为 `indirect` 时，可输出 OCR 片段或冲突原因，增强审计性。其代价是需要额外处理 OCR 失败、图片缺失和图文语义难以准确对齐的情况，因此完整 C6B 仍是后续重点。

### 3.9 可检验假设与研究贡献边界

本项目的主要假设可以归纳为：

1. 轻量级 VLM 经 LoRA 适配后，能够在离线环境中学习部分多模态提示注入模式；
2. 规则前置和 OCR 辅助能为直接、间接攻击提供与模型互补的证据；
3. 在严格的错误早退约束下，C4 有机会降低低风险样本的处理开销；
4. 统一的三分类基准与逐类安全指标能比 Accuracy 更可靠地揭示模型失效模式。

项目当前已经完成前述假设的工程化验证和部分策略筛选，但尚不能声称已经证明轻量级 VLM 可达到高可靠三分类检测能力。其可成立的贡献边界是：提出并实现了一套可复现的离线多模态提示注入研究框架，建立了以 Benchmark v2 为中心的可审计评测流程，并通过严格门禁暴露了当前模型在攻击类别边界上的限制。

项目按“问题定义—数据与模型准备—基线训练—优化实现—标准化评测—离线交付”的顺序推进：

### 4.2 模型与训练方案选择

项目选择 SmolVLM-500M 作为默认骨干。该模型的参数规模约为 5 亿，能够同时处理图像和文本，适合离线和边缘侧的轻量化研究定位。训练采用 LoRA 参数高效微调方式，并新增 MPID 三分类头；二者共同构成 MPID + LoRA。在冻结大部分预训练参数的情况下更新少量低秩参数，以降低本地训练的资源需求。

为兼顾稳定性与可执行性，项目将 macOS/MPS 主要用于开发和小规模 smoke，将 x86 CPU 路径作为较稳定的正式训练与评测路径；同时实现断点保存、恢复训练、运行日志和配置冻结机制。

### 4.3 数据集构造与选择

数据集围绕三类标签构建：

- `clean`：不包含劫持、覆盖或诱导系统指令意图的正常输入；
- `direct`：用户文本中显式出现指令覆盖、角色伪装、系统提示词泄露等攻击；
- `indirect`：攻击指令位于不可信外部内容或图像中，或由图文组合形成攻击语义。

Full-3000 训练集包含 3,000 条样本，三类各 1,000 条；其中包含 240 组可信边界三元组，用于加强三类之间的对比学习边界。数据构造过程中执行了标签分布、来源记录、文本规范化、去重键和训练/评测隔离审计。

### 4.6 优化机制的实现、验证与迭代

#### C4：高置信 clean 早退

C4 面向效率优化：当模型对 `clean` 的判断达到保守置信阈值时，可提前放行，避免后续不必要的处理。其安全约束是持续关注 `wrong_exit`，即不能将 `direct` 或 `indirect` 错误早退为正常输入。

#### C5：规则前置过滤

C5 面向直接注入的快速、可解释拦截。规则覆盖典型指令覆盖文本、伪系统身份、Unicode 异常、敏感指令模式等。规则命中时可直接阻断；规则未命中不等于放行，而是进入后续检测链路。该设计使规则层可独立更新和审计，并降低明显攻击样本对 VLM 推理资源的占用。

#### C6：跨模态检测与 OCR 增强

C6 用于补充图像内嵌攻击文本和图文矛盾等间接注入场景。项目在轻量接口基础上引入本地 OCR，提取图像像素中的文字，并基于显式指令覆盖、安全关闭、越狱和信息泄露等风险模式进行保守拦截。OCR 运行时与模型权重一并纳入离线包，验证了无网络依赖的像素级图像文本检测路径。

#### 多策略调优与门禁

项目在同一份 v2/smoke 数据、同一评测脚本和 `batch-size=1` 条件下，对 A-H、F2、F3、F4 等十一项策略进行横评。调优包括类别边界样本、direct margin、直接注入加权与课程策略等。所有策略先经过 smoke 筛选；未满足门槛时，不自动进入长时间正式训练，从流程上避免将训练资源投入到已表现出类别塌缩风险的策略中。

### 4.9 结果分析

1. **不能以 Accuracy 代替安全能力。** A 策略 Accuracy 达到 50.00%，但 direct Recall 为 0，说明模型无法识别显式攻击；该结果不能视为可用。
2. **F 是当前最平衡候选。** F 的 Macro F1 为 40.72%，direct F1 为 33.7%，在三类之间保持了相对可用的平衡；但仍未达到预设的 45% / 35% 门槛。
3. **F3 的数值优势不构成策略改善。** F3 的 Macro F1 仅比 F 高 0.05 个百分点，direct 指标没有变化，indirect F1 反而下降，不能证明改动有效。
4. **F4 存在单类过拟合。** 虽然 direct F1 提升至 35.3%，但 indirect Recall 从 F 的 36.4% 降至 18.2%，不符合三类安全性需共同满足的原则。
5. **当前主瓶颈是攻击类别边界。** F 策略在 53 条 direct 样本中仅正确识别 14 条，另有 25 条被判为 indirect、14 条被判为 clean，说明文本 direct 与其他类别之间的边界仍需重点优化。

### 4.10 最终结果结论

本项目的模型与策略筛选尚未达到既定放行阈值，且目前没有应作为最终能力结论的 v2/full 500 条正式验收结果。因此，结题结论应明确表述为：

> 项目已完成离线轻量级多模态提示注入检测原型、标准化 Benchmark v2、C4/C5/C6 多层防御和可复现交付链路；在统一 v2/smoke 策略筛选中得到相对平衡的候选方案，但该方案尚未通过预设门槛。当前成果适合作为后续数据、训练和防御机制优化的研究平台，不应表述为已达到生产级或高可靠三分类防护能力。

## 5. 项目执行复盘

### 5.1 有效做法

- 在项目中期建立冻结 Benchmark v2，并把策略筛选、正式评测和工程诊断严格区分；
- 使用 Macro F1、逐类 Recall/F1 和混淆矩阵，而不是单独追求 Accuracy；
- 保留配置、日志、预测文件、hash、数据审计和执行计划，使结果可追溯；
- 将模型、规则、跨模态检测和调度分层，形成可解释、可独立开关的 defense-in-depth 架构；
- 对未通过门槛的策略不自动启动长训练，避免以训练时长替代有效改进。

### 5.2 主要问题与影响

| 问题 | 影响 | 应对方式 |
|---|---|---|
| 类别边界不足与类别塌缩 | 攻击类 Recall 为零或显著偏低 | 均衡数据、边界三元组、统一 smoke 筛选 |
| loss 与 Macro F1 脱钩 | 训练表面收敛但安全指标无改善 | 用逐类 F1 和混淆矩阵作为训练门禁 |
| 长时间本地训练易中断 | 重跑成本高，实验节奏受影响 | 周期 checkpoint、恢复训练、阶段化执行 |
| MPS/CPU 平台稳定性和性能差异 | 训练速度、数值稳定性与脚本行为不一致 | 将 MPS 用于开发 smoke，x86 CPU 用于稳定执行 |
| OCR 与离线依赖复杂 | 打包体积、依赖管理和跨平台验证成本增加 | 采用本地运行时和包内模型资产，增加离线 smoke |

### 5.3 根因分析

项目的难点不仅在于三分类模型训练，还在于同时满足多模态、轻量化、离线、跨平台和可审计要求。模型参数规模与训练资源受到约束，攻击样本尤其是 direct 与 indirect 的边界又具有较高语义复杂度，导致简单的类别权重、margin 或短周期课程策略难以稳定改善三类表现。C4/C5/C6 可补充部分攻击模式和工程性能，但不能替代基础分类器对类别边界的学习。

### 5.4 后续执行改进原则

1. 先执行数据审计、短期 smoke 与阶段门禁，再考虑正式长训练；
2. 所有模型效果结论以 v2/full 独立验收为准；
3. 把 direct/indirect 边界错误按文本、OCR、图文矛盾、Unicode 混淆等类型分桶分析；
4. 长训练默认采用可中断、可恢复、可审计的作业方式；
5. 保持“未达标即不放行”的安全结论纪律。

## 6. 未来展望

### 6.1 数据与评测

- 扩充中文、英文、中英混合、Unicode 混淆、OCR 噪声和图文语义冲突样本；
- 增加 direct 与 indirect 的困难边界对和人工复核样本；
- 建立按攻击形式、语言、图像质量和风险强度分层的 Benchmark v2 后续版本；
- 在冻结的 v2/full 上完成独立正式评测，作为后续模型放行的唯一依据。

### 6.2 模型与训练

- 优化分类头初始化、损失函数和三类边界学习方法；
- 探索对比学习、困难样本挖掘、课程学习和更稳定的配对训练策略；
- 在稳定硬件环境下进行受控的 Full-3000 长训练，并在关键节点进行 v2/full 评测；
- 在资源允许时，比较其他端侧轻量 VLM 或探索视觉侧参数高效微调。

### 6.3 防御机制与部署

- 将 C4 从推理调度型早退逐步发展为中间层联合训练的早退机制；
- 对 C5 规则库实施版本管理、误报审计和灰度验证；
- 进一步提升 C6 的图文语义一致性能力，减少对单纯 OCR 关键词的依赖；
- 融合模型概率、规则证据、OCR 内容、Unicode 信号和图文一致性，形成可解释的风险评分；
- 探索 ONNX、MLX 等本地推理优化路径，改善 CPU 时延和内存占用。

### 6.4 结语

本项目完成了一个面向离线场景的轻量级多模态提示注入检测研究闭环：问题定义清晰、系统原型可运行、实验过程可追溯、结果评价有统一口径。下一阶段的重点不是单纯提高某一个指标，而是在冻结基准上同时实现“攻击不漏报、正常请求不过度误杀、离线系统可稳定运行”，从而将当前研究原型推进为更可信的端侧安全能力。
